Apply Desk now points to the connected Supabase project. Sign-up needs the database migration and Auth redirect URL configured below. The browser uses a publishable key; database policies keep each account’s rows private.

1. Create Supabase

The project is already connected. Open the Supabase dashboard to finish configuration. Free projects can pause after one week of inactivity, so the database may need waking when you return. Current pricing.

2. Apply the schema

In the project’s SQL Editor, run the migration in this repository: supabase/migrations/202610170001_apply_desk.sql. It creates profiles, applications, and email events with row-level security for each signed-in account. You can also use the documented database migration workflow.

3. Connect the web app

The frontend project URL and publishable key are already set in config.js. Do not use a service-role key here. In Supabase Auth → URL Configuration, set the site URL to https://damnsunnyy.github.io/ApplyDesk/ and add that same URL to the redirect allow list.

4. Enable free remote job search

Apply Desk uses the free public Himalayas remote jobs API. No API key or paid plan is required. Search runs through the Supabase Edge Function; it does not expose provider credentials. Install the Supabase CLI, log in, link this folder to your project, then deploy the function. Listings are remote roles; recognized countries are passed as eligibility filters, while city names map to their country where supported. Each result links to its original Himalayas listing and credits Himalayas as the source. The browser helper can fill known fields on a listing's application site. Optional auto-submit is limited to hostnames you explicitly allow and forms with no unanswered required fields.

5. Optional Gmail reply tracking

  1. In Google Cloud Console, select or create a project, open APIs & Services → Library, find Gmail API, and enable it. Google’s Gmail JavaScript quickstart shows the current console flow.
  2. Open Google Auth Platform → Branding and set the app name and support email. Under Audience, choose External. While the app is in Testing, add shubham.meghani.work@gmail.com as a test user. Testing mode is limited to listed users and Gmail test authorizations expire after seven days.
  3. Under Google Auth Platform → Data Access, request only https://www.googleapis.com/auth/gmail.readonly, the read-only Gmail scope Apply Desk uses.
  4. Under Google Auth Platform → Clients, create an OAuth client with application type Web application. Add this exact Authorized JavaScript origin: https://damnsunnyy.github.io. Do not add /ApplyDesk/ to the origin; origins cannot contain a path. Copy the Client ID. This browser app does not need the client secret.
  5. Set GOOGLE_OAUTH_CLIENT_ID in config.js to that Client ID, push the change to GitHub, and wait for Pages to redeploy. Then sign in to Apply Desk, click Connect Gmail, select the test-user account, and approve read-only access.

Each user must be added as a test user until you complete Google’s consent verification for public use. Apply Desk reads message subjects, senders, and short snippets; checks run only while the app is open. It does not read full message bodies or monitor the inbox in the background. Never publish a Google client secret.

Automation boundaries

The optional browser helper can submit a complete form only after you enable auto-submit and allowlist that exact host. It stops when it finds unknown required fields or sensitive declarations, and it cannot attach a résumé. Job sites use different forms and may restrict automation; confirm each site's rules. Gmail reply checks currently run while Apply Desk is open. Always-on inbox sync requires a separately deployed OAuth token store and scheduled server job; this repository does not yet include that connected service. Each friend must connect their own accounts.
